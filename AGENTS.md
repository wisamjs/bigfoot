## Bigfoot

- **Tickets**: before starting a Linear `BIG-n` ticket, fetch it with its relations; every "blocked by" ticket must be Done, otherwise stop and name the blockers. **Pick up** a ticket, named or next, with the `pick-up-ticket` skill; picking up covers the work and the PR, not only the worktree, so don't stop to ask before starting. Branch, commit titles, and PR name the ticket as `scripts/check-pr-naming.mjs` requires (CI runs it); the PR body starts `Closes BIG-n`, which closes the ticket on merge, so a ticket's work, docs included, ships in its one PR. A finished ticket ends with a pushed PR mapping each acceptance criterion to its change (here or in a PR it stacks on) and naming any step the user must do by hand; share the PR URL.
- **Review**: `CODING_STANDARDS.md`. CI's `review-gate` job holds every PR for the owner's click on **Review deployments** (`manual-review` environment); only a PR that changes nothing but `.md` files skips it (`scripts/review-needed.mjs`). So a finished ticket's PR waits for that click and is never merged by an agent.
- **Domain language**: `GLOSSARY.md`. Use its terms in code, UI copy, and tickets.
- **Spelling**: Canadian English with the Oxford comma everywhere, tickets included; cspell in `npm run verify` enforces it in the repo. Words and quoted US-spelled terms go in `cspell.json`.
- **UI work**: read `.claude/skills/typeui-design-system/` (TypeUI Candy) before writing or restyling components. Token values live only in `src/app/globals.css`. Primitives come from shadcn/ui (`components.json`): `npx shadcn add <name>` writes to `src/components/ui/`; restyle what it writes with Candy tokens before use (Button, Dialog, and Sheet show how), and build dialogs on `src/components/ui/modal.tsx`. Put new code where `CODING_STANDARDS.md` ("Where code goes") says; lint enforces who may import whom. **Keep Storybook current**: every change to a component in `src/components/ui/` or `src/features/` adds or updates its stories (`<name>.stories.tsx` beside it) in the same PR; `npm run stories` fails a component with none. `npm run storybook` shows the stories and the token page (`.storybook/tokens.mdx`); stories that need a Server Action get the spies in `src/app/**/__mocks__/actions.ts`. Before calling a layout done, look at it narrow and in dark mode: `npm run capture` (options in `scripts/capture.mjs`).
- **Verify**: `npm run verify` (spelling, design tokens, stories present, Python lint and format, `npm run test:api:unit`: the API unit tests, with no database and their own coverage floor, the OpenAPI schema, types, lint, then `npm test`: Vitest unit and component tests with a coverage floor, then `npm run test-storybook`: every story rendered in Chrome, failing on its play function or an axe violation). The pre-commit hook runs it, so committing is the verify run; a commit of only `.md` files runs just spelling. During that run the story tests also picture every Pages story, dark and light, in `docs/snapshots/` (rewriting only pictures whose pixels changed); the folder is git-ignored, so the pictures stay local. `npm run snapshots` retakes them alone; CI takes none. Then `npm run smoke` (every page in `scripts/pages.mjs`, signed in and out; fails on server errors logged to `.next/dev/logs/next-development.log`, which build and lint miss), then `npm run a11y` (axe-core WCAG 2.2 AA on the same pages and their `states`, such as open dialogs, light and dark, plus each dialog's keyboard focus and Escape, which component tests can't check). Smoke and a11y reuse this checkout's running servers or start their own; CI starts them cold, so when smoke is slow or flaky, read the CI run (`gh run list`) too. `npm run test:api` runs every API test, the database ones too, against Postgres. CI runs the same steps as parallel jobs (`fast-checks`, `unit-tests`, `storybook`, which also runs `npm run build-storybook`, `runtime`, `accessibility` in two shards; `A11Y_SHARD=1/2 npm run a11y` runs one locally) behind one required check, `ci-passed`. CI's database is a Postgres 17 service container on the runner (`DATABASE_URL=postgresql://postgres:postgres@localhost:5432/postgres`, no secret); run the same one locally with `docker run --rm -d -p 5432:5432 -e POSTGRES_PASSWORD=postgres postgres:17` and that `DATABASE_URL`. Only `migrations-applied` on pushes to `main` uses the Supabase dev database. In a fresh git worktree, run `npm run worktree:setup` first (`npm ci`, Chromium for the story tests, and `.env.local` from the main checkout); run it again after a merge that changes `package.json`. When CI fails, `npm run ci-failures` prints each failed job's log tail, readable in one go; `npm run pr-check` runs the PR naming check and the behind-`main` check before CI does.
- **Stale dev CSS**: stop `next dev` before `npm run build` (they share `.next/`). If a Tailwind class has no effect in dev (also after edits made outside the editor, e.g. `sed`), restart with `rm -rf .next/dev && npm run dev` before debugging; `npm run build` output is the authoritative CSS.
- **Signed-in pages without Google**: `node scripts/dev-session.mjs` prints an `authjs.session-token` cookie value for a test user; `node scripts/dev-applications.mjs add|remove` fills or empties their dashboard. `npm run screenshots` retakes the README screenshots.
- **TypeUI MCP installs**: results are too large to read; apply the saved result with `python3 scripts/typeui-apply.py <result-file>`.
