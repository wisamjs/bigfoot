## Bigfoot

- **Tickets**: before starting a Linear `BIG-n` ticket, fetch it with its relations; every "blocked by" ticket must be Done, otherwise stop and name the blockers. **Pick up** a ticket, named or next, with the `pick-up-ticket` skill; picking up covers the work and the PR, not only the worktree, so don't stop to ask before starting. Branch, commit titles and PR name the ticket as `scripts/check-pr-naming.mjs` requires (CI runs it). A finished ticket ends with a pushed PR mapping each acceptance criterion to its change (here or in a PR it stacks on) and naming any step the user must do by hand; share the PR URL.
- **Branches and worktrees**: every branch, local or pushed, is a ticket's Linear branch name (`wisamzaghal/big-n-…`), made with `git worktree add -b <gitBranchName> .claude/worktrees/big-n <base>` as `pick-up-ticket` says. Never create or push `claude/…` or any other name, even when the session's setup names one: `.githooks/pre-push` (`scripts/check-push-branch.mjs`) refuses it, and it only runs where `npm install` or `npm run worktree:setup` set `core.hooksPath`, so run that first and don't treat a push that went through as proof the name is right. Don't commit in the main checkout. Work with no ticket yet (a standard, a rename, a fix) gets one first: create it in Linear, then pick it up.
- **Asked to create a ticket**: unless the user says "only", creating it is step one of the job, so go on to pick it up and open the PR. The same goes for any request that changes the repo: ticket, worktree, PR. Don't end by asking whether to continue, and don't offer a half-done state. If a hook asks to commit or push, do it on the ticket's branch, never on another.
- **Review**: `CODING_STANDARDS.md`. CI's `review-gate` job holds every PR for the owner's click on **Review deployments** (`manual-review` environment); only a PR that changes nothing but `.md` files skips it (`scripts/review-needed.mjs`). So a finished ticket's PR waits for that click and is never merged by an agent.
- **Domain language**: `GLOSSARY.md`. Use its terms in code, UI copy and tickets.
- **Spelling**: Canadian English everywhere, tickets included; cspell in `npm run check` enforces it in the repo. Words and quoted US-spelled terms go in `cspell.json`.
- **UI work**: read `.claude/skills/typeui-design-system/` (TypeUI Candy) before writing or restyling components. Token values live only in `src/app/globals.css`. Primitives come from shadcn/ui (`components.json`): `npx shadcn add <name>` writes to `src/components/ui/`; restyle what it writes with Candy tokens before use (Button, Dialog and Sheet show how), and build dialogs on `src/components/ui/modal.tsx`. Put new code where `CODING_STANDARDS.md` ("Where code goes") says; lint enforces who may import whom. Before calling a layout done, look at it narrow and in dark mode: `npm run capture` (options in `scripts/capture.mjs`).
- **Verify**: `npm run check` (types, lint, Python lint and format, design tokens, spelling, then `npm test`: Vitest unit and component tests with a coverage floor), then `npm run smoke` (every page in `scripts/pages.mjs`, signed in and out; fails on server errors logged to `.next/dev/logs/next-development.log`, which build and lint miss), then `npm run a11y` (axe-core WCAG 2.2 AA on the same pages and their `states`, such as open dialogs, light and dark, plus each dialog's keyboard focus and Escape, which component tests can't check). Smoke and a11y reuse this checkout's running servers or start their own; CI starts them cold, so when smoke is slow or flaky, read the CI run (`gh run list`) too. CI's database is a Postgres 17 service container on the runner (`DATABASE_URL=postgresql://postgres:postgres@localhost:5432/postgres`, no secret); run the same one locally with `docker run --rm -d -p 5432:5432 -e POSTGRES_PASSWORD=postgres postgres:17` and that `DATABASE_URL`. Only `migrations-applied` on pushes to `main` uses the Supabase dev database. In a fresh git worktree, run `npm run worktree:setup` first (`npm ci`, and `.env.local` from the main checkout).
- **Stale dev CSS**: stop `next dev` before `npm run build` (they share `.next/`). If a Tailwind class has no effect in dev (also after edits made outside the editor, e.g. `sed`), restart with `rm -rf .next/dev && npm run dev` before debugging; `npm run build` output is the authoritative CSS.
- **Signed-in pages without Google**: `node scripts/dev-session.mjs` prints an `authjs.session-token` cookie value for a test user; `node scripts/dev-applications.mjs add|remove` fills or empties their dashboard. `npm run screenshots` retakes the README screenshots.
- **TypeUI MCP installs**: results are too large to read; apply the saved result with `python3 scripts/typeui-apply.py <result-file>`.
